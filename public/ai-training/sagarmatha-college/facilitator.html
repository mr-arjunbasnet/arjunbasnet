Before the session: switch on saving (one time, about 10 minutes)

AI or Not scores, the leaderboard and quiz answers are saved in Supabase. Until these steps are done, the pages show "Saving isn't switched on yet."

  1. Create a free project at supabase.com (any name, region Mumbai or Singapore for speed from Nepal).
  2. Supabase → SQL Editor → paste docs/sagarmatha-session/schema.sql from the website repo → Run.
  3. Supabase → Project Settings → API Keys: copy the Project URL and a secret key (sb_secret_…; never the publishable/anon key).
  4. Vercel → the website project → Settings → Environment Variables (Production): add SUPABASE_URL, SUPABASE_SECRET_KEY, and SAGARMATHA_ADMIN_KEY (any long password you choose).
  5. Vercel → Deployments → Redeploy the latest deployment so it picks up the variables.
  6. Check: open /api/sagarmatha/config. It should say "storage":"supabase". Play one test game, then delete that row in Supabase → Table Editor.

Your data afterwards: /ai-training/sagarmatha-college/results (enter your admin key: tables and CSV download), or Supabase → Table Editor → aion_games, quiz_responses and the aion_leaderboard view.

The three exercises in detail

Exercise 1 · 5 min · individual

Get on GitHub (phone track) · first local commit (laptop track)

Laptop track (from your draft): only for students who already have Git. Folder → index.html → git init → git add → git commit → git log. The same checklist is on the handout with tick boxes.

Phone track steps: github.com → Sign up with an email they'll keep after college → a professional username → verify the email. Those who already have an account help a neighbour, then star a repo.

Watch for: email verification delays on college Wi-Fi (switch to mobile data), and the "are you human" puzzle on slow phones. Anyone stuck finishes at home. Exercise 3 has a fallback.

Tip: mention the Student Developer Pack (education.github.com/pack), but don't do verification in class. It takes days and needs an ID photo.

Exercise 2 · 8 min · pairs

Prompt battle: lazy vs TEACH

Steps: each pair picks a task card. Partner A sends a lazy one-liner, Partner B builds a full TEACH prompt with the TEACH builder on the handout (five boxes become one copyable prompt) and sends it in the same tool, and they compare.

Task cards: 🅰 Explain a stuck topic (number systems, K-maps, loops, limits) · 🅱 A 2-week study plan for first-semester exams · 🅲 Debug the C program on slide 36 · 🅳 An extension email to a teacher.

Card C answers: (1) scanf("%d", n) should be scanf("%d", &n); (2) i < n should be i <= n (n = 5 gives 10 instead of 15). The prompt asks for hints, not fixes, which previews "tutor, not ghostwriter".

Debrief question: "Which TEACH letter made the biggest difference?" Expect Audience and How. For card D, point out if the AI invented the teacher's name or a reason: that's the placeholder lesson.

Exercise 3 · 10 min · individual

Ship it: an AI-drafted profile README, committed live

Steps: GitHub → + → New repository named exactly their username, Public, "Add a README file" ticked → fill in the pink fields of the TEACH prompt (slide 52, or the handout) and press Copy → edit the draft and delete anything untrue → paste into README.md → Commit changes with a real message → open github.com/username.

Common problems: a repo name that doesn't match the username exactly (the profile won't show it), or AI inflating skills ("passionate full-stack developer"). Tell them to delete it. Honesty is the point.

Privacy: first name and college are their choice. No phone numbers on a public profile.

Fallback: no account yet → draft with AI, save it in their notes, commit tonight.

Finish: 2–3 volunteers read out their URL and you open it on the projector. Applause. This is the photo moment.

Game · 7 min · individual

AI or Not?

Flow: QR → name, email, optional roll or section → images preload (so slow phones aren't penalised) → each image shows for 10 seconds with 📷 Real / ✨ AI → instant feedback with the tell → results with a per-image reveal. 100 points per correct answer plus up to 50 for speed. One game per email.

Fair play: answers and timing live on the server. The page never contains which images are AI, file names are random and photo metadata is stripped. Students who open DevTools find nothing.

Projector: open /leaderboard in a new tab (button on slide 44). It refreshes every 3 seconds and shows the join QR. Emails never appear.

Image pool: 8 real Nepal photos (Pexels, credited) and AI images generated for the session. A game draws up to 5 of each. To add or swap images, see src/lib/sagarmatha/images.ts.

Preparation checklist

The week before

  • Ask the coordinator for the room's projector input (HDMI/USB-C) and Wi-Fi details
  • Ask whether students bring phones or laptops, and roughly how many attend
  • Check the facts list below, especially model names and the Student Pack offer
  • Send the coordinator arjun-basnet.com.np/sagarmatha to share in advance (the handout has the Git install steps)
  • Switch on saving (the Supabase steps above) and play one test game

The day before

  • Run the whole deck once, timing each part against the run sheet
  • Test both live demos: the GitHub loop, and lazy vs TEACH in one AI tool
  • Delete any old csit-lab-demo repo so the demo starts clean
  • Download a copy of the slides to a USB stick as a backup

30 minutes before

  • Open /ai-training/sagarmatha-college/slides in Chrome, press F for fullscreen and P for the presenter view. Open /leaderboard in a second tab
  • Log in to GitHub and one AI tool in separate tabs
  • Test the countdown beep at room volume
  • Write the Wi-Fi details and arjun-basnet.com.np/sagarmatha on the board

If things go wrong

📶 No Wi-Fi

Students use mobile data. If nobody can connect, do Exercise 2 on paper (write both prompts, swap with a neighbour, critique using TEACH) and assign Exercises 1 and 3 as homework.

⏱️ Running late

Cut in this order: slide 14 (CV), slide 24 (landscape: summarise in one line), slide 37 (four hacks: point to the handout), slide 45 (AI or Not debrief: one sentence), slide 50 (7-day challenge: point to the handout). Protect AI or Not and Exercise 3.

⏩ Running early

Extend the Exercise 2 debrief: 3 pairs read their best prompts aloud and the class names the weakest TEACH letter. Or take more volunteers in Exercise 3.

🙊 Quiet room

Use fingers and hands for every vote, never cold-calling. Pairs share before individuals. Praise the first volunteer warmly. First-years in Nepal are often shy in the first 20 minutes, so it gets easier.

Engagement design: why it's built this way

Something to do every 5–7 minutes

Poll → predict → demo → exercise → quiz → game → exercise → game → exercise → quiz. Nobody sits through more than about 7 minutes of talking.

Examples from their week

C labs, scanf bugs, TU exams, K-maps, "dal bhat power 24 hour", Messenger zip files. The course's office personas are swapped for student life.

Everything connects

Git commits → AI agents that open pull requests → API keys leaking on GitHub → an AI-drafted README committed with Git. One story, not two talks.

They leave with something real

A live GitHub profile they can show friends tonight is far more memorable than any slide.
